# 63 OFFICE LIFE with SOORI — 운영 안내서

수리 꾸미기 + 공유 갤러리 사이트입니다. 이 문서는 **코드를 몰라도** 파츠·문구를 직접 관리할 수 있도록 정리했습니다.

---

## 1. 폴더 구조

| 파일 / 폴더 | 역할 | 직접 수정 |
|---|---|---|
| `content.js` | 인트로·안내 문구, 버튼 아래 작은 글씨, 알림 메시지 등 **모든 문구** | 자주 |
| `parts.json` | 탭 이름·순서, 각 탭에 들어갈 **파츠 목록** | 자주 |
| `parts/` | 파츠 이미지 (탭별 폴더) | 자주 |
| `design/` | 로고, 버튼 속 글자, 63빌딩 아이콘, 인트로 수리 그림 (SVG) | 가끔 |
| `firebase-config.js` | 공유 갤러리 연결 정보 | 처음 한 번 |
| `firestore.rules` | 갤러리 보안 규칙 (Firebase 콘솔에 붙여넣는 용도) | 처음 한 번 |
| `fonts/` | LIFEPLUS 폰트 (사원증 카드의 수리 닉네임용) | 거의 없음 |
| `index.html`, `style.css`, `app.js` | 화면 구조·디자인·동작 | 수정 불필요 |

## 2. 파츠 추가 · 교체 · 삭제

### 이미지 규칙
- **513 × 513px, 투명 배경 PNG**
- 기본형 수리(`parts/base/default-base.png`)와 같은 캔버스에서 **위치까지 맞춰** 그린 상태로 내보내기
- 파일 이름은 영문·숫자·하이픈만 (예: `hair-13.png`, `role-life-01.png`)

### 추가하기
1. 해당 탭 폴더에 PNG 업로드 (예: `parts/hair/hair-13.png`)
2. `parts.json`에서 그 탭의 `"files"` 목록에 파일 이름 한 줄 추가
   ```json
   "files": [
     "hair-12.png",
     "hair-13.png"
   ]
   ```
   - 목록 순서 = 화면에 보이는 순서
   - 줄 끝 쉼표(,)는 **마지막 줄에만 없어야** 합니다 (가장 흔한 실수)
3. 썸네일 확대, 눌러서 잡히는 영역은 사이트가 자동으로 계산합니다.

### 교체하기
같은 이름의 파일로 덮어쓰기만 하면 됩니다. `parts.json`은 그대로 둡니다.

### 삭제하기
`parts.json`에서 그 줄만 지웁니다. (이미지 파일은 남겨둬도 됩니다.)
→ 이미 갤러리에 올라간 수리 중 그 파츠를 쓴 것은, 그 요소만 빠진 채로 보입니다.

### 새 탭 만들기 (예: 계열사 역할)
1. `parts/role/` 폴더를 만들고 이미지 업로드
2. `parts.json`의 `"categories"`에 블록 추가 — 넣는 위치가 곧 탭 순서입니다.
   ```json
   {
     "key": "role",
     "label": "역할",
     "layer": 4,
     "files": ["role-life-01.png", "role-am-01.png"]
   }
   ```
   - `key` = 폴더 이름과 같게
   - `layer` = 처음 추가될 때 겹치는 높이 (1 의상 · 2 얼굴 · 3 눈썹 · 4 액세서리 · 5 헤어). 사용자는 이후 앞/뒤로 보내기로 자유롭게 바꿀 수 있어요.
   - 탭이 7개 이상이면 탭 글자가 좁아질 수 있으니 휴대폰에서 꼭 확인해 주세요.
   - `"fixed": true` 는 눈·입처럼 **위치 고정 + 하나만 선택**되는 탭에만 씁니다.

## 6. 처음 배포하기 — GitHub Pages
1. GitHub 로그인 (가능하면 **팀 공용 계정**) → 오른쪽 위 `+` → **New repository**
2. 이름 입력 (예: `63officelife`) → **Public** → Create
3. **uploading an existing file** 클릭 → 이 폴더 안의 **모든 파일·폴더를 끌어다 놓기** → Commit changes
4. 저장소의 **Settings → Pages** → Branch를 `main` / `/(root)`로 선택 → Save
5. 1~2분 뒤 표시되는 주소(`https://계정이름.github.io/63officelife/`)로 접속

> 파일 수정: 저장소에서 파일 클릭 → 연필 아이콘 → 수정 → Commit changes
> 이미지 추가: 폴더로 들어가서 Add file → Upload files

## 7. 공유 갤러리 연결 — Firebase (무료 Spark 요금제)
`firebase-config.js`가 비어 있으면 **미리보기 모드**(새로고침 시 갤러리 초기화)로 동작합니다.

1. https://console.firebase.google.com → **프로젝트 추가** (Google 애널리틱스는 꺼도 됨)
2. **빌드 → Authentication → 시작하기 → 로그인 방법 → 익명** 사용 설정
3. **빌드 → Firestore Database → 데이터베이스 만들기**
   - 위치: `asia-northeast3 (서울)` 권장 (나중에 변경 불가)
   - 프로덕션 모드로 시작
4. Firestore의 **규칙** 탭 → `firestore.rules` 내용을 통째로 붙여넣기 → **게시**
5. **프로젝트 설정(톱니바퀴) → 내 앱 → 웹(</>)** 앱 추가 → 나오는 `firebaseConfig` 값을 `firebase-config.js`에 붙여넣기
6. **Authentication → 설정 → 승인된 도메인**에 `계정이름.github.io` 추가
7. 사이트에서 수리를 올려보고, Firestore 화면에 `gallery` 항목이 생기면 완료

### 운영 참고
- **관리자 삭제**: Firestore Database → `gallery` → 해당 문서 → 문서 삭제
  (문서의 `caption`이 수리 닉네임, `nickname`이 작성자 닉네임)
- **내 게시물 삭제**와 갤러리의 **"내 수리" 보기**는 올린 **같은 기기·같은 브라우저**에서만 됩니다. (로그인 없이 브라우저별 익명 ID로 구분)
- "내 수리"를 누르면 그 사람이 올린 게시물 수만큼만 읽기가 발생합니다.
- 무료 한도: 하루 읽기 5만 건. 갤러리는 한 번에 30개씩 불러오므로 하루 약 1,600회 열람까지 무료입니다.
  (`firebase-config.js`의 `GALLERY_PAGE_SIZE`로 조절)
- 한도를 넘으면 그날은 갤러리만 멈추고 다음 날 풀립니다. 요금은 나오지 않습니다.
- 유료(Blaze)로 전환할 경우 반드시 **예산 알림**을 설정하세요.
